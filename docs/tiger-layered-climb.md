## 制作范围与素材状态

场景表示二十八道拐的一小段爬坡。人物沿窄山路前进，近处岩壁先挡住江谷，随后岩肩退开，金沙江与对岸山体逐渐显露。侧视镜头保持人物和脚下道路可读，不靠抬高镜头完成开景。

`climb-layout.ts` 将样段定义为约 28 米的艺术化路径。这个数值用于步速、脚步和镜头节奏，不是实测路段长度，也不表示复原全部二十八道弯。连续行走约 20–30 秒是制作目标，尚未实测。停步、环顾、拍照会延长停留时间。

画面沿用已有虎跳峡手绘水彩资产。内置 imagegen 新制作了八帧右向侧视步行动画，并已接入场景。游戏素材为 `dist/sprites/tiger-hiker-side-v1.webp`，1760 × 880，每格 440 × 440。脚底按逐帧鞋底锚点对齐，可见人物高度只作等比归一。提示词、原图和处理方式见 [人物素材说明](../art/tiger-layered/hiker-side-v1.md)。落脚、平顺性和实际透明混合效果仍待集中验证。

本轮不新增 Tripo、Spine 或其他付费依赖。Three.js 几何样段、Tripo 参考图、Blender 制作脚本与模型加载准备保留，新的 PixiJS 场景不加载这些旧渲染路径。没有生成或精修 Tripo 模型，也没有请求 API 或消耗 Tripo 积分。

## 地图与场景共用路线进度

旅程中的 `state.progress` 是地图和爬坡段共用的路线进度。`tigerJourney.climbSection` 只保存二十八道拐的路段范围，不另存一份行走进度。

`highSection()` 使用现有 OSM 命名小路两端在历史高路轨迹上的投影，得到 `startFraction` 和 `endFraction`。场景内的 0–1 进度对应这个范围，不新增伪精确 GPS 点。

`createMountainWalkGame()` 接收 `routeProgress.read()` 与 `routeProgress.write(sceneProgress)`。进入或重试时，`read()` 从 `state.progress` 反算场景位置。人物实际前进后，`write()` 把进度写回同一个 `state.progress`，只允许前进。相机、人物和地图由这份进度衔接，退出不会把地图送回起点。

快捷入口直接进入爬坡样段。仅打开入口不增加路线进度，首次实际前行才映射到二十八道拐所在路段。普通地图行进仍可在该地标进入同一场景。

场景打开期间可以越过沿途照片的展示进度。返回地图并继续行走后，原有 `Journey.tick()` 仍展示尚未查看的照片，保留 `pending`、`visited` 与来源信息。此时将地图进度保留在已走位置，避免旧照片阈值让人物倒退。没有提前把照片标记为已查看或已收藏。

## 操作、暂停与收藏边界

当前操作文案为“轻点停走，按住慢行，拖动看看山谷”。键盘保留停走、前行、环顾与回正视线。拍照、回正视线和收藏是独立操作，不再增加左右移动或调角度面板。

退出爬坡后，地图停在当前路线进度。当前段内显示“继续这段山路”，再次进入从同一位置继续。抵达山肩但尚未收画时，可返回看江处拍照；继续走出该段后不再显示这个段内入口。

抵达不等于收藏。玩家到达看江处并主动拍下、收好画面，才会沿用现有完成流程生成图文手帐。途中拍照、未完成退出或仅看风景都不新增记录。截图失败保留可重试状态，不用固定徽章代替失败截图。

手帐沿用现有去重与首次作品保留规则。旧记录、实景照片及其授权信息不清理，不新增导入、导出或清空入口。重玩不重复生成同一地点的手帐页。

场景沿用项目的帧循环和场景管理器。后台、失焦与退出应释放输入并停止行走，避免迟到脚步或重复奖励。减少动态效果、资源加载失败、重试和退出恢复仍需集中验证。

## 环境声音

`gorgeOpenness` 表示近处岩肩退开后江谷的可见程度。`src/app.js` 将连续值交给音频场景，江声的音量与频段随开景变化，不只在阶段切换时跳变。脚步由实际行走距离触发，停步不继续补播。

本轮复用项目已有免费声音，包括 Kenney CC0 材质声音和已有署名水声、叶声录音。通用声音经游戏混音构成山谷声景，不能称为金沙江或虎跳峡现场实录。来源和修改说明保留在站点声音署名及现有声音文档中。没有新增付费声音服务。

声音仍由玩家主动开启，沿用静音和后台暂停。音量层次、循环衔接、手机外放效果与画面对应关系尚未人工试听。
