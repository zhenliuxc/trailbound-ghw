# 主地图画面比例调整 · 2026-10-16

用户截图指出画面比例失衡：武功山树木和人物相对控件偏大，顶部“看看这里”的发现画作被裁切。此次只调整本地主地图展示，不改路线玩法、虎跳峡四段实现、手帐数据或站点发布状态。

## 原因与实现

主地图原始逻辑画布为 720×600，由矢量景物、参考路线和单独的 UI 标记组成。此前桌面固定世界宽度 720，再令可见高度等于 `720 / 容器宽高比`；宽幅约 2.28:1 时只显示中部约 316 单位高度。路线和打卡点按裁切高度缩小，树木与山体维持原尺寸，人物及发现画作又分别缩放，造成相对大小失衡和顶部截断。

- 保留已加宽、增高的容器。桌面保留完整 720×600 中央画作，按窗口比例向两侧展开景物；大屏场景放大上限为 1.45 倍。参考路线固定使用原等比投影，地理形状不随窗口比例压扁。
- 跟随镜头改为较轻的放大，最高 1.6 倍；视野和概览保持同一宽高比。SVG 和 Pixi 继续使用同一相机变换。
- 人物目标高度 44–68 CSS px、发现画作宽度 48–64 CSS px、打卡点直径 36–44 CSS px，按可用高度选取；标签保持 12 CSS px，路线线宽独立于缩放。打卡点触控范围仍至少 60 CSS px。
- 发现画作和下方文字按实际屏幕裁切范围留边；包括手机 `slice` 取景。打卡点名字在边缘可调整位置，离开视口的标签不悬浮到屏幕边缘。
- 扩展既有地色的外围端点、草木和纸张笔触分布，避免宽屏两侧只有空背景。景物密度上限为原来的三倍；内部山体、河流、路线坐标和原有画风保留。武功山通用场景和九溪独立绘本场景均接入。
- 容器尺寸变化时重新取景并重建发现提示，修正重绘后保留旧发现 ID、导致提示不再出现的问题；退出时断开尺寸观察并清理延迟重绘。

主要源码：`src/runtime/map-viewport.ts`、`src/app.js`、`dist/scenery.js`、`dist/illustration.js`、`dist/style.css`。生成脚本仍通过 `npm run build` 更新 `dist/runtime.js` 与 `dist/app.js`。
