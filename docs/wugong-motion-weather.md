# 武功山动作与时间天气

2026-10-17。用户要求继续优化上下坡、脚踩实路面、转弯和随行镜头，细化地图并增加时间天气，询问可减少手工制作的库或脚手架。只改武功山独立行走页，沿用用户已经明确给出的完整行走测试授权。未发布或提交。

## 实现

`model.ts` 继续管理路线、进度、六站照片和营地事件。新增 `gait.ts` 单独管理左右脚，步态只有支撑和摆动两种状态。同一时刻最多一只脚摆动，支撑脚的地形坐标和鞋底角度固定。摆脚按路线进度与横向落点插值，重新查询实际地形高度，再叠加抬脚弧线。停步时用短促的落脚过程收住脚，不把半空的绘制位置当成地面；到站落稳后再打开照片。

坡度和弯道同时影响步长、步速和摆脚时间。上坡缩步、微前倾并增加抬脚高度；下坡缩步、屈膝、降低重心并延长承重转移。身体参考支撑脚高度，腿部保留两段关节解算并限制伸展。鞋底结合地面坡度、脚跟落下和脚尖离地绘制，脚下阴影只随承重出现。

身体朝向连续插值并限制转速，脸、背包和躯干按转向逐渐过渡。急弯减速，反向先转身再恢复步速。镜头使用带速度的临界阻尼，缩短并按弯度收回预瞄，只跟路线中心，不读取脚点、重心起伏或呼吸。

新增 `environment.ts` 管理游戏内景象。第一天从上午走向营地黄昏，休息时渐入夜色；点击次日出发后过渡到第二天晨光，再逐渐走向白天。晴、多云、薄雾与小雨随旅程缓变。顶部景象选项可独立选择光照和天气，不改变路程或到站记录。它不是实时气象预报。

天空、远山、光照、谷雾、雨丝与风使用同一环境状态。天气变化不重新生成整幅地形，云在山体之后绘制，近处谷雾保持低透明度。静态路肩加入地形投影的碎石、草叶和林缘灌丛，下山段补少量树木；高处保持开阔。草叶与围巾共享风势，减少动态效果时去掉环境漂移和雨丝运动。照片、后台暂停与退出沿用原生命周期。

默认随行、全图切换、人物小比例、七个统一纯图标和六站区域实景说明继续保留。时间天气没有写入旧旅程或手帐，不产生新奖励。

## 设计比较

比较了模型内的距离相位步态与独立的落脚规划器，采用后者，将落脚调度从路线事件中移出。模型仍是规划器的唯一调用者，未引入第二个行走循环。保留前者的固定接触点、鞋朝向、腿部伸展上限和短镜头预瞄。只在路线状态中增加到站收步阶段，照片与营地状态没有复制。

两个候选与评阅均使用当前可用的同一模型，不是跨模型证据。架构比较只做源码阅读和设计。实际构建、模型检查和浏览器结果另行记录。

## 第三方工具建议

当前山体已由高程数据导出和采样脚本生成，再由 Canvas 绘制。后续更需要可视化场景编辑和统一人物动作，单独增加噪声库或换瓦片库不能解决脚底承重和坡地转身。

| 工具 | 能减少的工作 | 对当前工程的取舍 |
| --- | --- | --- |
| [Three.js + Rapier](https://rapier.rs/docs/user_guides/javascript/character_controller/) | 控制器提供斜坡、台阶和贴地移动，减少自行处理碰撞的代码 | 工程已有 Three.js。适合后续独立立体样段，脚底仍需动画与 IK 配合；本轮未接入 Rapier |
| [Three.js CCDIKSolver](https://threejs.org/docs/pages/CCDIKSolver.html) | 为带骨骼的 SkinnedMesh 解算 IK | 需要统一骨骼人物和足底目标；当前程序关节人物不能直接套用 |
| [Babylon.js Editor](https://editor.babylonjs.com/) | 可视化组织场景、模型、脚本和项目 | 更接近完整游戏场景脚手架，切换需要迁移当前渲染与交互，不自动替换本站 |
| [Blender Geometry Nodes](https://docs.blender.org/manual/en/3.0/modeling/geometry_nodes/point/distribute_points_on_faces.html) | 按地形表面、密度和种子分布植被与石块 | 适合建立可重复导出的布景流程，保留真实山体与艺术调整；不会自动决定路线构图 |

建议保留现有网页壳和路线数据，把未来立体场景放在已有 Three.js 中，使用可视化地形布景、统一人物骨骼和 Rapier 控制器。若更重视一体化场景编辑，再选 Babylon.js Editor。本轮没有新增引擎依赖、购买素材或迁移其他路线。
