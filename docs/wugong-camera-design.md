## 问题与边界

用户要求更高分辨率、更大的武功山地图，能够切换贴近小人的视角与全图。默认保持全图，仍只走已有林间上坡、草甸转弯、营地坐下样段；不改其他路线，不扩展后续路线玩法。

## 现状追踪

`main.ts:start` 加载数值高程，建立 `Landscape`、`Trail`、`WalkModel` 与 `WalkRenderer`。`WalkModel` 用固定场景坐标推进路程和脚部接触。`Landscape.project` 将高程投影到 1200 × 860 的逻辑画布。

`WalkRenderer.resize` 按全图比例设置 view，将当时可见范围的地形、植被与道路生成一张 Canvas 背景，采样密度上限为每场景单位 2 像素。`paint` 只复用该背景并叠加人物、近景道具与动草。地形只有 241 × 281 个采样点，近景道具纹理也固定为 2 倍密度。仅放大 view 会同时暴露背景范围不足与纹理像素不足。

点击使用 `toScene` 反变换；DOM 地标使用 `toScreen`，但只在 resize 后更新，且离屏标记会挤在边缘。随行时必须共用当前镜头变换、逐帧更新可见地标。镜头跟随路线上稳定的落脚位置，不能跟随身体每步起伏。

后台、页面隐藏和销毁分别暂停或取消动画；异步背景构建已有代次与 AbortSignal，需延续这一取消边界。缓存生成、视角切换和重走都不能重置行走、营地或声音状态。

## 比较准则

1. 放大后有足够的地形、植被与道具细节，不能只拉伸全图背景。
2. 手机与桌面有明确缓存上限，镜头移动不逐帧重画整幅地形。
3. 地形、人物、道路、地标与点击始终共用一个变换，离屏图标不堆在边缘。
4. 保持较小的入口接口与单一坐标定义，生成脚本可重复执行。
5. 模式切换、移动、隐藏和退出期间的构建有取消、复用及可见回退。

## 设计比较与最终结构

两份独立设计分别为常驻全图加超扫近景窗口，以及四级 512 像素分块金字塔。当前可玩样段短，采用前者作为实现基底：常驻全图、一个已完成的近景窗口、最多一个正在生成的新窗口。镜头进入窗口边缘时才更新近景，完成后整体替换，重建期间继续显示已有背景。

父任务和独立交叉审阅均选择单窗口结构。交叉审阅按五项分别为单窗口 4/3/4/5/4、分块 4/4/4/3/5，同为 20 分；前者的缓存状态和接缝问题较少。保留分块方案的两项约束：完整记录实际 Canvas 像素与几何缓存占用，隐藏、尺寸变更、销毁时拒绝迟到结果。取消逐块调度、多级预取和离屏 Worker，当前没有运行证据要求它们。

默认 Claude/Grok 设计模型未在本会话提供，比较采用可用的 GPT 设计席与继承模型。候选仅写各自临时目录，主任务是唯一仓库写入者。上述评分是静态设计比较，不是运行验证。

### 调用方式先行

```ts
await renderer.resize(width, height, signal);
renderer.setCameraMode('follow');
const frame = renderer.paint(model, reduced, dt);
const placement = frame.marker(anchor, cssOffset);
const point = frame.sceneFromCanvas(canvasLocalCssPoint);
```

`camera.ts` 拥有视角、稳定路径跟随、缩放与平移，并产生捕获当帧数值的只读投影。`backdrop.ts` 集中管理一次编译的地形空间索引、全图与近景生成、串行构建、覆盖判断、回退和内存上限。`renderer.ts` 组合背景与动态物件，按实际显示密度缓存并剔除离屏道具。`main.ts` 只选择模式、使用同一投影放地标和反算点击。

```ts
type CameraMode = 'overview' | 'follow';
type MarkerPlacement = { kind: 'visible'; point: Readonly<Point> } | { kind: 'hidden' };
interface FrameProjection {
  readonly mode: CameraMode;
  readonly bounds: Readonly<SceneBounds>;
  sceneFromCanvas(local: Point): Point;
  marker(anchor: Point, cssOffset: Point): MarkerPlacement;
}
```

场景坐标仍是 1200 × 860，路线长度、步速和营地状态不随像素数改变。近景目标密度最高每场景单位 6.4 像素，整图等效最高 7680 × 5504。预算不足时降低背景采样密度，不擅自改变用户镜头距离。手机全图和单个近景缓冲分别最多 250 万和 320 万像素；桌面为 500 万和 800 万。前台 Canvas、生成中的缓冲、程序树冠与前景精灵另有明确上限。

背景覆盖实际宽高比产生的场景外延，并包含随行镜头可达范围。天空与远山采用固定世界坐标，不随近景窗口重置。全图与新窗口都使用新 481 × 561 数据；全图可用隔点网格，近景使用完整网格。

接受近景短暂从全图清晰度补到目标清晰度，以换取镜头切换不中断行走。更密的显示采样不等于提高原始地理测量精度。移动端内存、近景细节和镜头实际舒适度仍须获准后实测。

### 分配账本与收尾

背景只串行生成一张新 Canvas。手机常驻全图、已有近景、生成中的近景合计最多约 35.6 MB RGBA 像素，桌面约 84 MB；窗口 resize 时包含旧全图及新全图的暂存。前台 Canvas 像素另限手机 200 万、桌面 500 万。近景树冠程序纹理按实际像素计数淘汰，手机 4 MiB、桌面 8 MiB；前景精灵为 12/24 MiB，并先剔除离屏物件。

准备后的顶点 XY、RGB 和深度分别使用 Float32Array、Uint8Array 和 Float32Array，本轮网格共约 4.05 MB；空间桶复用数值 cell ID，查询结果只在单个串行任务期间保留。JSON 数值数组、JS 索引容器、Canvas 驱动侧及浏览器自身的额外开销不包含在上述 RGBA 数字内，不能当作整进程内存或真机测量结果。

静态核对修正了随行状态 resize 后的全图外延、返回全图过渡期的标记隐藏、异步恢复后的代次检查，以及已有全图时构建失败应保留回退。首次加载失败仍展示原有重试入口。未运行体验测试；构建完成与否记录在样段交付文档。
