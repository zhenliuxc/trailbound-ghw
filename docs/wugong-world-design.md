## 保留 SVG 长卷，统一世界坐标

方案 A 保留 SVG 人物、道路和可访问标记，在约 `3600 × 900` 的长卷中逐段展开水彩。现有照片及小游戏入口可以直接复用，减少跨渲染器同步。

方案 B 把人物、背景、前景及点击判定都迁到同一渲染器，更容易统一深度排序，但需要重做现有 SVG 人物和交互。本轮先吸收它的坐标约束。人物脚底、道路、停留点、前景遮挡及点击区域都使用长卷世界坐标，镜头只做一次世界到屏幕的变换。

现有 Pixi 画布在 SVG 后面，因此只给 Pixi 增加前景不能遮住 SVG 人物。本轮透明水彩前景进入 SVG 人物之后的独立层，依据物件脚点和人物脚点决定显示顺序。Pixi 与 SVG 使用同一目标镜头，不各自推进行进状态。

`wugong-world.ts` 只保存只读艺术数据并计算位置、阶段和目标镜头。它不持有 DOM、动画帧、音频、进度状态或第二个时钟。应用现有帧循环传入 `state.progress`，统一推进镜头缓动、步态和雾层。

## 艺术路径与真实数据的边界

长卷用 11 个控制点安排森林、上坡、草甸、山脊和山顶。控制点的横坐标持续前进，纵坐标表现山路的回转与爬升。所有点继续绑定现有 `0–1` 路线进度，交给 `createVisualRoute` 生成平滑曲线。

路径中的 `elevation` 是美术坡度示意值，只供角色姿态或画面编排使用，不是 GPS 实测海拔。应用的体力、寒意、路线长度和真实海拔继续读取原有路线与状态模型。

照片仍在 `.25` 山脊草甸、`.5` 云海观景和 `1` 金顶远眺触发。照片文件、作者、许可及访问入口沿用当前数据。森林在 `.12` 结束，草甸在 `.24` 出现，避免 `.25` 照片触发时人物仍在树林。

云海在 `.46` 之前完全隐藏，在 `.46–.58` 之间平滑展开。远山和近雾可以共用展开比例，不能提前在开场背景中完整露出云海。

## 阶段与停留点

`wugongPhase(progress)` 返回阶段、云海展开比例及艺术坡度建议。阶段区间依次为森林 `0–.12`、上坡 `.12–.24`、草甸 `.24–.48`、山脊 `.48–.88` 和山顶 `.88–1`。`slope` 为 `0–1` 艺术强度，`leanDegrees` 为前倾角建议，`strideScale` 为步幅建议。它们不修改原始路线度量、地点顺序与照片进度锚点。接入后上坡会缩放交给原旅程的帧时间，使人物每一步前移更短、整段走得更慢；体力、寒意和天气仍按原旅程时钟推进。这是游戏中的坡度表现，不是现实步速或海拔测量。

`wugongNearby(progress)` 只返回最近且已进入临近范围的一个停留点，否则返回 `null`。营地位于 `.34`，范围为前后 `.025`，提供休息。观景石位于 `.55`，范围为前后 `.028`，提供看云海、照片和速写入口。金顶停留位于 `.97`，范围为前后 `.03`。

停留点是画面中的位置，不是新建的真实地名或打卡照片。休息、看景和侧视动画不直接发放奖励。照片继续调用原有照片控制器，完成互动仍通过 `miniController`、`rewardController` 和 `journalController` 收进手帐。

## 目标镜头与调用草图

`wugongViewport(width, height, progress, point)` 返回保持容器宽高比的局部镜头。桌面世界宽度约 `900–1250`，小屏约 `430–600`。镜头向前看 `80` 个世界单位，在地形边界保留少量绘画留白。镜头只依赖人物路径脚点，不读取步态位移或身体摆动。

函数只给出目标矩形。现有帧循环负责缓动、死区、后台暂停和减少动态效果。窗口变化重新计算矩形，不重建路线，不重置已经触发的停留或侧视状态。

侧视与停留使用场景会话，打开照片、手帐或奖励时暂停；关闭后仅恢复此前正在行进的状态。切后台、换路线和退出应取消延迟回调及声音，避免迟到的动画和重复奖励。
