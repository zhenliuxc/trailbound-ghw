# 地点图标设计流程与规范

适用于山径现行 2D 行进地图的地点图标。图标表达地景类别，中文名称标识具体地点。手帐收藏使用独立的圆形手绘徽章，其构图、纸边、素材与旧画兼容见[旅行手帐徽章设计规范](journal-badge-design-guide.md)。

本规范整理自七条路线的共用图标实现与实际检查。尺寸、组件和构建方式是当前实现；图形辨识度与审美认可须另行确认。各轮问题、检查结果与截图保留在对应版本记录中，不作为永久规则累积。

## 设计流程

1. **核对地点与地景。** 明确地点名称、路线顺序、场景锚点、主要地貌，以及是否属于起终点、过夜点或照片地点。图标的含义来自当地可见特征，不能只根据地名联想造型。
2. **先复用类别，再补充符号。** 在图标库中寻找已有类别。同类地景共用图形，由名称区分具体地点；现有类别不能表达关键特征时才新增。
3. **提取识别特征。** 一个图标突出一个主体，用少量辅助特征补充。例如竹林保留细竿、竹节和尖叶；瀑布保留垂直落差；山口保留两坡之间的凹口。
4. **先检查小尺寸，再完善大图。** 在 24 px 下判断轮廓与关键结构是否仍清楚，再检查 26 px 和 30 px。辨认困难时先删去重复线条，拉开结构间距，再调整线宽。并排比较容易混淆的类别。
5. **放回真实地图。** 使用地图的统一投影定位，接入名称避让和路线可用状态。在山体、植被、水面与不同光照背景上查看，检查地名、人物、道路和控件是否互相遮挡。
6. **按授权集中验收。** 检查桌面与手机实际尺寸、镜头切换、点击和照片往返。修复失败项后复测相关行为，保存截图与结论。分别记录实现完成、功能验收与用户视觉确认。

## 图形语义

| 地景 | 优先保留的特征 | 容易造成误读的做法 |
| --- | --- | --- |
| 竹林 | 有节的细竿、分枝尖叶 | 宽圆叶片、普通树冠 |
| 森林 | 树干与成组树冠 | 与草丛相同的短线 |
| 草甸 | 舒缓坡面、少量草簇 | 密集竖线、尖刺纹理 |
| 干海子、草地盆地 | 两侧坡缘、低洼地面 | 容器轮廓承托植物 |
| 山顶 | 突出的峰形、山面结构 | 与营地帐篷共用相同三角形 |
| 山脊、山口 | 连续脊线、两山间凹口 | 仅换方向或颜色的山峰 |
| 沙滩、急流、溪谷、瀑布 | 弧形岸线、礁石折浪、纵向曲流、垂直落差 | 所有水域都用相同波纹 |
| 茶园 | 茶叶和种植垄线 | 泛用叶子或茶杯代替地景 |

颜色提供辅助识别。缩小或去掉类别配色后，主要差异仍应由轮廓与结构表达。装饰不承担地点身份，不用光圈、发光或尺寸变化强调普通标记。

## 视觉与尺寸

米白圆底、草木绿线描、圆角线端与连接。内部留白按视觉重量平衡；同样的画布尺寸还须检查不同图形看起来是否一样大。细节不能挤到圆形边缘。

| 项目 | 当前基准 |
| --- | --- |
| SVG 坐标画布 | `40 × 40` |
| 圆底 | 中心 `20,20`，半径 `18` |
| 主线颜色 | `#4b6854` |
| 圆底颜色 | `#fbf8e9`，不透明度 `0.94` |
| 普通外圈 | `#a4ad8a`，线宽 `1.1` 个 SVG 单位 |
| 内部主线 | `1.85` 个 SVG 单位，24 px 显示时约 `1.11 px` |
| 随行图标 | `30 px` |
| 桌面全图图标 | `26 px` |
| 小屏全图图标 | `24 px`，当前以地图容器宽度小于 `460 px` 切换 |
| 按钮命中区 | `44 × 44 px`，与图形显示尺寸分开 |

表中的显示尺寸与命中尺寸均为 CSS 像素，不是设备像素。以后调整参数时，修改共用源，让地图、独立 SVG 和预览一起更新。

## 地图排布与交互

- 图标中心固定在地景投影点，跟随缩放重新投影。名称在附近四个方向避让，不移动地标锚点，也不添加远距离连接线。
- 图标与纯文字地名共用占用空间，同时避让视角按钮、章节条和容器边界。上一帧的名称方位仍能容纳时继续沿用，减少镜头移动中的跳换。
- 起终点和主要照片地点优先保留。在拥挤全图中，次要且不可点击的符号可以收起，保留附近名称与说明；随行时恢复。次要地名空间不足时按优先级显示，不能靠叠字展示全部信息。
- 缩放时使用不同的收起和恢复间距，避免符号在临界距离反复闪现。所有仍显示的同级图标保持统一尺寸。
- 图标类别与点击状态分开。是否可点由路线提供；已到达且可重看照片的地点加深外圈，保持原图形。不能仅凭颜色判断交互是否可用。
- 图标按钮须接收指针事件。收起的符号、透明余量与纯文字背景标注不能挡住邻近按钮。可操作地点具备中文可访问名称、键盘焦点和明确的禁用状态。
- 地图不显示小游戏入口标记。小游戏随行进触发，完成后的手绘徽章按收藏流程独立展示。

## 共用实现

| 内容 | 唯一维护位置 |
| --- | --- |
| 图形、类别名称、尺寸常量 | `src/journey/landmark-symbol.ts` |
| 地点按钮、投影、可用与到达状态 | `src/journey/landmark-layer.ts` |
| 次要地理名称 | `src/journey/landmark-name-layer.ts` |
| 标签避让与密集符号处理 | `src/journey/landmark-label.ts` |
| 标记样式 | `src/journey/landmark-markers.css` |
| 图标预览页面 | `src/templates/landmark-library.html` |

路线配置图标类别、中文名称、地景锚点和可用状态。需要时提供名称优先方向、起终点说明和次要级别；路线自身处理照片与行程。新路线沿用上述组件，不再复制一套 SVG 或名称排布。

`npm run build` 通过 `scripts/build-landmark-library.mjs` 生成 `dist/icons/landmarks/*.svg`、`dist/landmark-markers.css` 和 `dist/landmark-library.html`。这些生成文件不直接编辑。

## 验收依据

- **识别。** 24 px 下能看清关键特征。对照检查山顶与营地、山脊与山口、各类水域，以及竹林与普通森林。总览大图只用于查看笔形，不能替代小尺寸检查。
- **布局。** 地点仍对应正确地景；主要名称保留；文字、圆形图标和控件互不遮挡。圆形外缘与文字矩形分别检查，透明包围盒角相交不直接判为圆底重叠。
- **稳定。** 跟随、全图和屏幕尺寸切换后位置正确，名称不无故跳换，符号不在临界距离闪现。
- **操作。** 实际点击图标中心与可用文字区域，确认没有穿透到画布，也没有被透明标记挡住。检查照片打开、关闭和重看；确认键盘焦点与触控区域可用。
- **复用。** 地图、SVG 下载和预览来自同一图形源。新类别有中文名称、类型定义和实际使用位置。

自动检查负责坐标、碰撞与状态规则。浏览器操作负责验证真实显示和点击行为。手机模拟、真机体验、听感及用户审美确认分别记录，不互相替代。
