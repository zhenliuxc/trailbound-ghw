# 麦理浩径：人物转向

2026-10-20。用户要求优化小人行走时的转向。本轮只调整麦理浩径行走页，继续使用现有两位 Q 版旅人、PixiJS 和八帧行走素材。

## 改动

原来固定朝右起步，以朝向阈值加 0.3 秒等待直接镜像人物。现在起步就参考山路方向；当前行进朝向与前方一小段路径一致、并持续走过一定距离后，才确认折返。近乎纵向的路段和短促反向折线保持原朝向。

真正换向在第 2 或第 6 个收脚姿态发生。以各角色已有的脚底接触坐标为支点补偿位置，再随下一步回到路径中心，减少镜像瞬间脚底跳动。人物身体的倾斜单独平滑处理，暂停不继续累积转向，调整窗口与切换全图不消耗步数。角色选择保留当前朝向。

逻辑在 `src/maclehose-walk/turning.ts`，由同目录 `scene.ts` 接入。阴影不参与人物镜像。未添加行走透明度变化、压扁缩放或新依赖。未改其他路线、地理位置、照片、事件与手帐流程。

## 检查

沿用用户已经授权的麦理浩径完整行走检查。`npm run build` 完成编译打包；`node --test tests/maclehose-turning.test.cjs` 七项通过：

- 起步朝向、小幅反向与纵向弯道过滤。
- 当前方向和前路需一致；在收脚阶段才换向。
- 两位角色在平路与斜坡倾身时，镜像前后接触脚的位置一致，补偿随步子收回。
- 暂停、恢复、零时间重绘及减少动态效果。
- 按真实路线模型以 30 和 60 帧推进，均到达北潭凹，均有十次方向变化；变化位置的差异控制在一个落脚半步内。

最后一项是模型行进检查，照片和小游戏用既有完成／跳过接口推进，不能称为本轮完整浏览器玩过五关。起初的测试把“转向动作必须发生在西湾山照片之后”作为断言，但前方路径会让收脚换向发生在山顶附近；已改为检查实际下坡路段的朝向。另将不同帧率的时间差按收脚间隔比较，不要求量化到同一个采样点。

实际浏览器分别使用蓝衣旅人、双辫旅人从浪茄走到西湾山，检查连续折弯、到达停步、暂停选角及恢复后的朝向。双辫旅人的连续画面采样保存在 `docs/previews/maclehose-turning-11/bend-00.png` 至 `bend-15.png`，可见左行、转向右行、再随山路左行；没有将合成示意图当作运行截图。测试后恢复原先的蓝衣旅人。浏览器检查未记录警告或错误。

证据目录另有起步、选角后停步、最终预览截图和专项测试输出。本轮没有进行实体手机、GPU 性能或人工音频验收，也没有重跑全部小游戏。未提交、推送或发布；视觉自然程度仍由用户查看本地预览确认。
