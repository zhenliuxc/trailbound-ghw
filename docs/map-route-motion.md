# 主地图路线与人物朝向

2026-10-17，本轮只处理主地图的路线画法、人物朝向和镜头跟随。用户已明确放弃此前分层爬坡样段方向；该样段快捷入口和沿途自动进入已停用，素材与源码保留。没有更改其他路线的小游戏规则、照片、手帐或存储数据。

## 同一条曲线用于绘制与行走

`src/runtime/visual-route.ts` 从投影后的参考路线生成艺术化曲线。它先按 8 个地图坐标单位的容差消除小折点，再以短控制柄三次曲线连接。控制点限制在相邻段的范围内，保留起终点、照片点和虎跳峡命名地标的进度锚点。这里的距离是 720 × 600 绘图坐标，不是 GPS 米数。

`src/app.js` 将整条路线、已走部分、人物脚底、脚印、照片标记、命名地标、发现点、风景留白及路线缩略图接到同一份曲线几何。已走部分截取原曲线，不再对 GPS 前缀重新简化。人物不会继续沿地图已经省略的小折点移动。

原始路线、累计距离和 `state.progress` 仍用于旅程进度、地点顺序及事件触发。平滑只调整展示，不把简化后的线长冒充真实徒步距离，也不重新计算照片的触发进度。

## 朝向与镜头保持稳定

人物参考前方约 28 个绘图单位的总体方向，末端使用最后一段方向。`src/runtime/map-heading.ts` 对方向做时间滤波，忽略约 8° 内的小转角。水平分量超过 ±0.28，并明确反向持续 0.22 秒后，人物才翻面。接近竖直和停步时保留上一朝向。换路线和重玩时按起始路段重新初始化，普通刷新不重置。

镜头追踪曲线上的位置，使用与帧时间有关的阻尼及约 1.2 屏幕像素的死区。暂停、声音开关及一般界面刷新不再隐式跳到目标相机。首次布局、窗口重排和主动切换总览时仍重新取景。SVG 与 Pixi 背景继续共用相同相机，不增加另一套镜头循环。
