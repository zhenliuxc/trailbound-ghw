## 已实现

| 互动 | 操作与判定 | 圆形手帐 |
| --- | --- | --- |
| 转过山弯 | 三块始终正向的山路画片，拖放或点选后点缺口；错放不扣分。已接通的连续山路驱动现有 Q 版人物走高，镜头从较近的山径缓缓拉开。三块放对且人物走完才进入完成过渡。 | 山弯初见，使用配套圆形水彩画作 |
| 记住山色 | 客栈桌上四张画片、两对山影与窗灯，进入时重排。错配短暂翻回，两对找到后完成。 | 半山灯火，使用配套圆形水彩画作 |
| 涂一页山色 | 三点颜料可选，只涂速写上的岩壁、草木两处留白；真实笔触覆盖各区域至少约 62% 才完成，等待或单点不能领奖。保留原画纸纹与线稿，不要求描边。 | 崖间飞瀑，圆形画芯保存本次笔触与配色 |
| 把江声留下 | 拖动圆形取景窗，使江心巨石轮廓和近旁白浪入窗，松手自动拍下。初始圆窗不满足目标，取消手势不触发拍摄。删除调焦、连拍、选片和手动收藏。 | 江声入峡，保存实际圆窗内的构图及快门时的水流状态 |

规则位于 `src/runtime/tiger-memories/model.ts`、`rules.ts`、`layout.ts`。四种会话分开建模，完成流程为 playing、settling、capturing、complete，截图失败独立进入可重试状态。没有完成判定或没有可保存画面时不发奖。

画面由 `view.ts` 使用浏览器 Canvas 2D 合成现有手绘、纸片、笔触、局部水流和 Q 版图集，不迁移地图引擎或增加依赖。地图仍由现有 PixiJS 渲染。画面与命中共用同一缩放和留边变换，宽高等比；小屏单独安排画片与速写位置。Canvas 像素预算限制为约 300 万，素材在进入时加载并复用，未做性能验收。

键盘保留选片与放片、翻画片、选色和移动画笔、移动圆窗与拍摄；R 重试。离开画面焦点、切后台和取消手势停止笔触，不通过后台等待增加完成度。减少动态效果会缩短行走反馈与完成停留，并停止水流动态。

## 行程与入帐

`src/tiger-walk/route.ts` 的四个事件改用新 ID，地图不新增游戏图标：

1. 二十八道拐爬升前触发拼片；成功接回高点前约 110 个场景单位，继续走后再打开观景实拍。
2. 中途客栈先保留原有实拍，回到地图坐下约六秒后展开画片。完成、徽章入帐和淡回地图后进入余下休息，再衔接过夜与清晨。退出未完成游戏仍能过夜，不补发徽章。
3. 瀑布实拍结束后继续走约 135 个场景单位，再触发涂色，避免立即连弹。
4. 只有选择中虎跳支线并走到江边，才在实拍后的另一段停步触发圆窗取景；完成或退出后都接同一条小路上返，返回中峡客栈结束，不重复触发。

沿用发现提示、手绘淡入、完成结果停留、圆形画芯显出、自动入帐、徽章淡出与返回地图。截图提取发生在本游戏状态中，失败可以重试保存画面或退出。收藏写入失败继续沿用现有的重试保存流程。

`src/wugong-walk/art-page.ts` 仅在虎跳峡页面注册新适配器，复用公共小游戏、奖励及手帐控制器；其他路线不启用这些事件。`dist/discoveries.js` 追加新目录项和圆形画作，`dist/audio-scenes.js` 只追加四个新 ID 的声景映射。使用项目已打包且有许可记录的风、水声、纸张拟音、布料及快门拟音，无新增付费素材；声音默认仍由用户主动开启。

新 ID 区分本轮新玩法与历史玩法。旧记录、日期、文字、画作及旧源码保留，不把旧通关当作新小游戏已完成。同一新 ID 再次完成仍由现有手帐去重，保留第一次同等完成记录。固定画作只保存版本化引用；两处个人创作保存有大小上限的圆形 WebP 截图。不提供清空、导入或导出。
