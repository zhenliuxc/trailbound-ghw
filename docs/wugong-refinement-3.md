## 五项失败的修复

五项失败均发生于旧首页测试装载阶段，尚未执行游戏；简化 DOM 缺少原生 `append`，而且用例还从首页观察按钮进入，已经不符合当前武功山独立手绘页。

为测试夹具补齐 `append`，并让武功山用例装载实际生成的 `wugong-art.html` 与 `wugong-art.js`，通过公开输入调用现有小游戏、奖励和手帐控制器。主地图与其他路线不为测试绕过入口。断言同步到当前收藏规则：游戏完成展开画作时没有写手帐，主动点击“收进手帐”才保存并通知行走页。

五项原失败均已通过：四游戏未完成退出、云海/拍照/拼图两种宽高下完成收藏、纸鸢完整飞行、纸鸢资源失败与重试、云海资源失败时阻止输入。另补充退出已完成画作仍不收藏，以及实际独立页重玩保留首次日期、文字和画作。

浏览器还发现并修复了营地拍照的首次方向键问题：进入取景时，通用输入坐标仍保留在旧位置，第一次横向移动会同时把镜头移低。现在进入取景时同步到当前取景框，回归用例与真实浏览器均确认第一次方向键后可以正常拍照。新生成的手帐引言同时使用当前行程的地点，避免吊马桩仍写成旧场景“金顶山脊”；已保存记录不被改写。

下山开始时还有一处提示边界：人在金顶精确位置点击下山，旧比较要求已经越过金顶才切换下山文字，而界面只在状态变化时重绘。将比较改为包含金顶位置，开始下山就使用下山提示。此为末尾文案边界修正，已重新构建和检查源码，没有为一条提示再完整重走路线。

本轮相关检查最终共 25 项通过：行走与图标 7 项、故事规则 8 项、独立页与收藏 10 项。只在新增修复后复查受影响文件，没有重复执行整个仓库的测试。最新独立页检查输出见 [art-checks.txt](previews/wugong-refinement-3/art-checks.txt)。模拟 DOM 与数值检查不算真实浏览器或实体手机结果。

## 浏览器记录

实际到站顺序为 `start → slope → meadow → camp → horse → summit → end`。从东江村正常出发，走过绝望坡和草甸，到观音宕坐下并主动过夜；次日经吊马桩、金顶，主动开始景区下山后连续走到大门。没有注入坐标、加速时钟、跳过夜晚或伪造完成事件。终点实读为第二天、`finished`、13:25，本程完成并收好 4 幅手绘，见 [walk-result.json](previews/wugong-refinement-3/walk-result.json)。

四种小游戏都在实际抵达后从照片卡片进入，完成并点击收藏再回到原行程：纸鸢以方向键牵线完整飞过三个阶段；营地拍照包括发现失焦取景问题、退出不发新奖、修复后重新取景、展示与告别；拨云使用画面坐标直接点击三片实际云团，云团外的点击没有进度；拼图用公开的数字辅助选片并直接点击画框放下，错误位置给出反馈，正确放满六片才完成。

营地夜晚打开手帐，打开前与停留后都保持 `sleeping`、第一天 20:35；关闭手帐后才继续过夜与清晨收包。终点手帐按武功山筛选仍为四个标签，四张图片均实际加载，草浪来信的大图与文字可读。已有云海开信仍保留旧记录的“金顶山脊”位置，未被本轮重玩覆盖为吊马桩；新记录才使用新地点。重新出发后再看手帐，仍只有四段回忆，没有清空或重复新增。

浏览器读取的警告与错误日志为空。手机宽度 390px 完成了小游戏、照片、夜晚与手帐操作，320px 全图的初版布局发现第三个图标过低，修复后重新载入最终构建单独复查。该布局与最后一条下山提示修正后未重复完整行走；不将此记录说成实体手机、GPU 性能压力或人工听感验收。
