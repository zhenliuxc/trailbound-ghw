# 山径 Trailbound · 游戏理念与设计美学约定

版本：1.1  
确认日期：2026-10-18

这份约定是后续路线、场景、人物、地图、小游戏、声音和旅行手帐的共同判断标准。用户提出新的明确方向时，以用户的新指示为准；除此之外，旧讨论稿和实验记录与本约定冲突的部分不再作为实施依据。

## 一、已确认的产品方向

**山径以 2D 山野行走、地点事件和旅行手帐收集为核心。背景地图使用程序绘制的 2D 示意图，精细手绘与真实照片在实际到达后的事件中展开。**

2026-10-18 最新修订：用户认为整幅手绘地图的制作成本过高，明确要求主背景改用 2D 示意图。保留已选定的大眼睛 Q 版人物、地点关系、行走、跟随／全图和手帐。用户随后已授权补全武功山东江村反穿两天一夜，观音宕过夜，经金顶下到景区大门；其他路线不自动重做。

2D 地图通过简化山形、等高线、林带、草甸色块和连续路线表达地理关系，可有分层与轻微动效。地图无需生成整幅手绘底画；精细水彩继续用于地点事件、小游戏与收藏，不引入实时 3D 漫游。

武功山 `wugong-3d.html`、Three.js 全程以及其他 3D 试片保留为实验和参考，不接入主流程，不继续扩建。后续资源投入集中在清楚的 2D 地图、路线叙事、地点互动的精细手绘和手帐收藏。

## 二、一句话体验

这是有地域感、可以慢慢走进去的山野徒步游戏；沿途看风景、遇见地点、完成一小段有因果的互动，最后把当时的水彩画和记忆收进一本旅行手帐。

玩家记住的应是一座山、一条路和一次停留，而不是一组功能按钮或一项渲染技术。

## 三、五个不可交换的设计支柱

1. **地点先于任务。**
   每个场景先回答“这里为什么值得走、值得停”，再决定放什么玩法。路线、植物、天气、动物、衣着和物候必须来自当地环境与当前季节。

2. **行走和观看是主体。**
   玩家应先感到在坡上、林缘、草甸或山脊行走，再遇到互动。不能用等待、计时或重复操作代替空间与风景。

3. **地图负责行程，手绘负责停留与纪念。**
   行走背景使用可复用的程序化 2D 示意图。实际到达后，真实照片说明地点，精细水彩承载互动与纪念。两者沿用米白、草木绿、青灰和克制暖金的品牌色。

4. **手帐是旅途的结果。**
   完成一段真实发生的互动，才能得到对应的图文与水彩纪念。手帐把地点、日期、画面和文字串成回忆，不用收藏进度墙代替体验。

5. **安静、克制、有留白。**
   画面允许风和雾占据时间，文字与按钮只在需要时出现。避免全屏装饰、过度发光、画面堆满 HUD，以及“漂亮背景上贴一个简陋物件”。

## 四、核心体验闭环

```text
选择路线
  → 沿 2D 示意山路行走
  → 靠近地点，空间里出现少量提示
  → 抵达并触发与地点有关的互动
  → 完成互动，展开水彩纪念与文字
  → 收进旅行手帐
  → 回到山路，继续前往下一段
```

未完成互动不发奖励；跳过、退出或只观看不生成完成记录。同一互动重玩不重复新增手帐，首次完成保留原有文字、日期和画作。

## 五、2D 地图的呈现原则

### 1. 两个尺度

- **行走视图**：默认沿路线跟随人物，只展示眼前一段山路。镜头向前留出空间，让下一处转弯或地景自然出现。
- **总览地图**：由用户主动切换，展示整条路线的山脊、沟谷、林带、草甸、两天行程、起点终点和地点图标。

两者共享路线进度、海拔变化和地点数据，但使用不同的细节层级。行走视图负责沉浸，总览地图负责方向感。

### 2. 程序化 2D 示意图

山形、支脊、沟谷、林地、草甸和路线使用可复用的矢量形状与少量图标绘制。减少背景素材依赖和逐图手绘成本，以形状与色块区分地理主题。人物、道路、草木和地点共享世界坐标，支持必要的遮挡；不能出现道路悬空、人物漂移或阴影脱节。

### 3. 一条清楚的主路

道路使用连续、平滑的浅土色曲线，保留真正影响方向感的重要转弯，过滤 GPS 级的细碎折线。主路始终是画面中第二清楚的对象，人物是第一清楚的对象。装饰纹理、草丛和岩石不能压过人物和路线。

### 4. 每段只讲一个地理主题

同一时刻突出远、中、近三层信息即可。森林、草甸、裸岩、溪流、沟谷、云海和村舍按路段依次出现，不把整条路线的元素同时铺满一屏。

场景之间用山形、植被色块和光色变化连接。转场要让玩家感到继续往山里走，而不是切换幻灯片。

### 5. 用构图表达海拔

2D 不等于平面。陡坡通过道路斜率、山体轮廓、人物姿态和镜头高度共同表达；上坡时地平线抬升、天空减少，进入草甸和山脊时天空重新展开，登顶时远山退到人物身后。高低差可以艺术化调整，但同一场景内的道路、人物脚点、石块、帐篷和植被必须落在同一地表逻辑上。

### 6. 总览是一张 2D 路线示意图

总览只保留辨识山脉和行程所需的信息：主山脊、主要支脊、沟谷、森林与草甸色块、连续路线、起终点、营地、观景点和少量统一图标。地点之间要有呼吸空间；点击图标可看介绍，实际抵达事件仍由行走触发。

总览不追求与 GPS 完全一致。真实地点、先后顺序和路线关系必须正确，画面位置可为构图调整。

## 六、路线气质与场景语法

每条路线必须有自己的地理主角，不能共用同一背景换颜色。

- 武功山：草甸、风、山脊、云海和两天一夜的营地记忆。
- 莫干山：竹林、雨声、石阶和湿润苔痕。
- 九溪：溪水、石头、落叶和茶园。
- 虎跳峡：峡谷高差、金沙江与高路视野。
- 其他路线继续以真实地理、物候和旅途关系为准。

以武功山东江村经典反穿为例，场景顺序建立如下记忆：

| 路段 | 主地理意象 | 玩家感受到的变化 |
| --- | --- | --- |
| 东江村 | 低处村舍与林带 | 从村口进入山路 |
| 林间爬升 | 树干遮挡、树冠与坡面 | 视野收窄，身体持续向上 |
| 绝望坡 | 之字坡与岩块 | 林带变薄，天空逐渐变多 |
| 高山草甸 | 开阔草坡、风带与远山 | 视野突然打开 |
| 观音宕营地 | 山坳、帐篷、暖光与暮色 | 停步、休息、过夜 |
| 吊马桩与山脊 | 连续脊线、侧边沟谷、云海下缘 | 高处行走与俯瞰感 |
| 金顶 | 山顶石碑、层叠远山与云海 | 全程最高点与回望 |
| 景区下山 | 长折返、山谷与重新出现的林带 | 回到低处，旅程收束 |

段落可以因画面需要缩短或扩大，但地点顺序、路线关系和抵达意义不能随意改变。

## 七、人物与动效

- 人物使用用户指定的大眼睛 Q 版徒步形象，沿用 `art/characters/walk-source-v2.png`。大小需与地图协调，保持脚点贴合路面。此前对大眼睛和头身比的概括限制由本条更新。
- 上坡缩短步幅并轻微前倾，下坡降低重心并控制落脚；转弯先减速再连续转身。
- 镜头跟随路线中心，采用缓动和死区，不跟随呼吸、每一步起伏或草木摆动抖动。
- 背景、人物和前景各自独立运动。风吹草、云影、雾层、围巾或背包的次级动作必须与同一环境时钟一致。
- 动效必须有因果：风推动草，叶子积雨后才落滴，人物停下后背包才卸下。不能为了“有动画”而悬浮、闪烁或无故变形。

## 八、地点、照片与互动

- 2026-10-18 武功山更新：地图展示打卡点的统一图标和名称，小游戏不显示地图入口，随行进与场景状态触发。先实现观音宕营地入夜、星空小游戏、收藏手绘手帐及清晨出发，其他路线保持现状。人物继续使用已指定的大眼睛 Q 版。此条更新此前仅靠近才显示地名的武功山要求。
- 每条旅程有清楚的起点、终点；带支线时同时说明主线终点、支线目的地和返回关系。
- 沿途只保留少量地点。靠近后才出现地名或操作提示，避免满屏按钮。
- 地点图标统一大小和线宽。抵达时自动停步，再打开对应实景照片、文字和来源信息。
- 区域照片必须说明使用边界，不能把区域照片写成该弯道的定点实拍。
- 小游戏优先用鼠标或触屏直接操作画面，一个核心动词能说明主要动作。已有按钮若能由画面操作替代，应移除。
- 小游戏要有明确目标、即时反馈和真实完成条件。不能靠等待、随便点击空白处或滑完整幅背景自动发奖。
- 同一路线的互动机制应有变化；可以复用底层能力，但不能只换背景和素材。

## 九、声音

声音是旅途体验的一部分。环境声、脚步、风和材质声、操作反馈、完成仪式与配乐分层存在，音量克制，并与画面发生在同一时空。

音乐与音效必须使用许可清楚的免费素材，保留作者、来源、许可和修改记录。通用录音不能写成当地实录。音频遵守用户主动开启、静音、切后台暂停和退出清理。

## 十、旅行手帐

- 图画与回忆合并为一处旅行手帐，排列为标签墙；点击标签打开大图、地点、日期、天气、完整回忆和相关山野知识。
- 只有完成互动才形成图文记录。未完成、跳过或只观看不生成奖励。
- 每段地理记忆对应一张主水彩画，不为了填满界面重复发放相似图。
- 手机与电脑保持整齐，不分成“旅途回忆”和“收藏图鉴”两套视图。
- 保留自动保存、路线筛选、去重和旧记录兼容；不提供清空、导入或导出。

## 十一、界面与可访问性

- UI 融入水彩画风，形状和提示保持清楚，不遮挡道路、人物和互动主体。
- 地图视角切换放在地图内右上角；进入路线默认跟随，只有用户主动操作才查看全图。
- 主要触控目标不小于 44px。手机不是桌面缩小版，也不只适配手机。
- 键盘、鼠标、触屏都可完成主要流程。提供暂停、退出、重试和减少动态效果。
- 后台切换、照片、手帐和奖励打开时暂停行进与环境时钟；返回后不补播迟到的动画和声音。

## 十二、视觉禁区

以下效果不能作为交付画面：

- 用粗糙占位图形代替地点事件和纪念画的精细手绘。主地图允许简洁、完整的程序化矢量示意图。
- 漂亮水彩背景上贴比例、光照和笔触不一致的简陋人物或物件。
- 整张图长期只有一种绿色，森林、草甸、裸岩和远山没有层次。
- 巨大的前景树木、房屋或图标长期挡住人物和道路。
- 道路悬空、人物脚底脱离坡面、地点图标与真实位置分离。
- 满屏按钮、状态卡、发光描边、重复提示和装饰性 UI。
- 以“技术能跑通”“整程能到达”替代画面与体验验收。

## 十三、反跑偏规则

1. 主流程继续使用 2D、PixiJS 和旅行手帐体系，示意地图与事件手绘各负其责。引入实时 3D、自由漫游或完整游戏引擎迁移前，必须先说明它解决了哪一个现有体验问题，并取得用户明确确认。
2. 一个实验页面效果不错，不自动成为主流程。它先作为独立预览，得到用户确认后才决定是否复用其中经验。
3. 先完成一段能代表最终品质的基准场景，再铺满整条路线。不能先追求全程覆盖，再反复返工统一风格。
4. 每次扩展只处理用户指定的路线与范围。可复用数据与组件，不把一段确认自动扩大为所有路线重做。
5. 功能完成、自动检查、浏览器验收、真机体验和发布是不同状态，汇报时必须分开。

## 十四、完成标准

一场路线体验达到可交付状态，至少应同时满足：

- 人物、道路和当前地理主体在画面中第一眼可辨。
- 每段路线有不同但统一的地理气质，森林、草甸、山脊和山顶不会只是换色。
- 人物贴地行走，上下坡和转弯自然，镜头稳定。
- 地点具有可停留的互动，抵达照片、介绍与来源完整。
- 完成互动后获得有意义的水彩纪念，并能顺畅收进旅行手帐。
- 总览能回答“走过哪里、现在大概在哪一段、下一处是什么”，同时保留清楚、安静的山野气质。
- 电脑与手机都能完成主要流程。
- 画面经得起实际观看，不把引擎、资源数量或测试通过当作美学验收。

## 十五、确认记录

2026-10-18，用户明确确认以 **2D + 手绘 + 旅途中的手帐收集** 为游戏主方向。该确认更新此前以武功山完整 3D 为主线的探索方向；3D 全程、Three.js 场景和相关实验源码保留，不再作为主游戏继续开发。

后续若用户再次提出改变媒介、核心玩法或美术语言，应先记录变更原因、影响范围和新的验收标准，再修改本约定。局部实现细节可调整，本约定中的产品气质与体验闭环不因技术便利自行改变。

2026-10-18 后续调整：用户明确要求背景地图不再使用手绘，原因是制作成本过高；改用程序化 2D 示意图，实际触发地点事件时展开精细手绘与真实照片。保留用户指定的大眼睛 Q 版人物和手帐收集。本次修改武功山样段，其他路线保持原样；旧水彩背景素材归档，不再作为该样段运行依赖。
